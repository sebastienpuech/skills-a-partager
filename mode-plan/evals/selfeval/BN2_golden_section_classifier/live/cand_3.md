# §10bis. Harnais & signal de succès

Le skill ne « marche » que si ses classifications tiennent face à un jeu de référence figé. On maintient un **golden set** de 60-100 tickets réels annotés à la main (catégorie attendue + cas ambigus documentés), stratifié pour couvrir chaque catégorie, y compris les rares. Le **signal de succès primaire** est l'exactitude top-1 sur ce golden set (cible ≥ 90 %), doublée d'une **matrice de confusion** pour repérer les paires de catégories systématiquement confondues (ex. « facturation » vs « remboursement »). On suit aussi le **taux de tickets non classés / « autre »** : une dérive à la hausse signale un angle mort de la taxonomie plutôt qu'une erreur du classifieur. Un **run de non-régression** rejoue le golden set à chaque modification du prompt ou de la taxonomie ; toute baisse d'exactitude ou nouvelle confusion bloque la livraison. En production, on échantillonne chaque semaine 20 tickets classés pour un audit humain rapide (accord/désaccord), ce qui alimente le golden set et calibre le seuil de bascule vers l'escalade manuelle. Enfin, on trace le **taux d'escalade** (tickets renvoyés à un humain faute de confiance suffisante) : trop haut, le skill n'apporte rien ; trop bas, il tranche des cas qu'il devrait déférer.
